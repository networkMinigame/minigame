# 미니게임 목록 기준안

> 확정안이 아니라 **기준안**. 아직 게임 정하는 중이라 후보가 계속 추가/교체될 수 있음.

## 1. 형식과 인원

| 형식 | 2인 | 3인 | 4인 |
|---|---|---|---|
| **개인전 (FFA)** | O | O | O |
| **2:2 팀전** (짝수 전용) | X | X | O |
| **1:나머지** | X (1:1이면 그냥 개인전) | O (1:2) | O (1:3) |

- 3인일 때 짝수 팀전은 안 나옴 (형식 단위로 제한)
- 1:2와 1:3은 **"1:나머지" 형식 하나**로 묶음. 밸런스는 상대 수로 계산 (예: 보스 체력 = 기본값 x 상대 수)
- 꼭 특정 인원에서만 되는 게임이 생기면 "형식 + 인원 제한"을 같이 선언

## 2. 선정 규칙

- 미니게임마다 **형식만 선언**하고, 형식이 인원수 가능 여부를 판단
- **매 라운드 현재 인원으로 다시 필터링** (4인 → 한 명 나가면 다음 라운드부터 3인 풀)
- **겹치지 않게 뽑기**: 풀을 섞어서 순서대로 꺼내고, 다 쓰면 다시 섞기
- **2:2 팀 나누기**: 현재 순위 기준 1등+4등 vs 2등+3등
- **1:나머지의 "1"은 현재 1등**: 혼자 이기면 보상 크게 (예: 왕관 2개)
- **2:2 도중 한 명이 나가면**: 남은 1명이 그 판 끝까지 진행, 다음 라운드부터 3인 풀

## 4. 추가 후보 상세

### 11. 키노피오 세기 (참고: 슈퍼 마리오 파티)

- **진행**: 열차 칸을 돌아다니며 키노피오 수를 셈 → 시간 종료 → 정답과 각자 답을 동시에 공개 → 가장 가까운 사람 승리
- **재미**: 동시 공개의 긴장감, 돌아다니고 숨는 NPC 때문에 헷갈림, 조작 실력이 아니라 관찰력 싸움
- **장점**: 지연에 강함 (터널링 OK), Swing 구현 쉬움 (옆에서 본 2D 열차, 의자를 앞 레이어로 그리면 숨는 효과)
- **동시성**
  - 플레이어끼리는 충돌 없음. 동시성 거리는 NPC 쪽
  - NPC 1마리 = 스레드 1개. 수십~수백 마리가 움직이는 동안 서버는 계속 위치를 읽어서 보냄 (읽기/쓰기 충돌)
  - 칸 사이 이동이 원자적이지 않으면 한 마리가 두 칸에 동시에 있거나 어디에도 없는 순간 발생 → **서버 정답 자체가 틀어짐**. 은행 송금 총액 문제와 같은 구조. 두 칸을 같이 잠그면 데드락 → 칸 번호 순으로 잠가서 해결
  - 답 제출: 전원 제출까지 대기 후 공개 (`CountDownLatch` / `CyclicBarrier`), 시간 초과 시 현재 값으로 마감
- **변형 (선택)**: 역 정차로 NPC가 타고 내림 / "파란 모자만 세기" 같은 조건 / 정확히 맞히면 보너스 왕관

### 12. 어깨빵 피하기 (참고: 슈퍼 마리오 파티 "마지막까지 살아남자")

- **진행**: 격자 경기장, 가장자리에서 NPC가 줄(가로/세로)을 따라 돌진 → 피하기. 3번 맞으면 탈락, 마지막 생존자 승리. 탈락 순서로 등수
- **재미**: 예고를 보고 피할 칸을 고르는 판단, 점점 많아지는 돌진, 남은 목숨 차이로 생기는 역전
- **장점**: 격자 기반이라 Swing 구현 쉬움. 돌진 줄을 미리 예고하면 지연이 있어도 공정함. 판정은 서버
- **동시성**
  - 돌진 NPC마다 스레드 (또는 `ScheduledExecutorService`로 웨이브 생성), 시간이 갈수록 빈도 증가
  - **칸 점유 경쟁**: 플레이어가 칸에 들어가는 순간 NPC도 들어오면 누가 먼저인가
  - **무적시간 check-then-act**: 두 NPC에 동시에 맞으면 목숨이 1개 깎여야 하는데, "무적 아니면 → 목숨 -1 → 무적 시작"이 원자적이지 않으면 2개가 깎임. CAS로 상태 전환
  - **탈락 순서 / 마지막 생존자**: 생존자 수 `decrementAndGet`, 같은 순간 두 명 탈락 시 동순위 처리
- **변형 (선택)**: **1:나머지 버전**으로도 가능. "1"이 돌진할 줄을 직접 고르고, 나머지가 피하기

### 13. 클러셔 뚫기 (참고: 슈퍼 마리오 파티 "클러셔로부터 도망치자", 규칙은 변형)

원작은 뒤에서 쫓아오는 클러셔를 피해 도망치는 게임. 우리 버전은 방향과 규칙을 바꿈.

- **화면**: 고정 (스크롤 없음)
- **진행**
  - 클러셔가 **오른쪽에서 왼쪽으로** 몰려옴. **왼쪽 끝은 낭떠러지**
  - 클러셔마다 **속도가 다름** → 빠른 애가 느린 애 뒤에 막혀서 **벽**이 되기도 하고, 무리 사이에 **틈(길)**이 생기기도 함
  - 플레이어는 밀려나지 않게 버티다가 틈이 보이면 **앞(오른쪽)으로 뚫고 나감**
  - 낭떠러지로 떨어지면 탈락
- **승리**
  - **최후의 1인**이 남으면 그 자리에서 종료, 단독 승리
  - **시간 제한**이 끝났을 때 살아 있는 사람은 **공동 승리** (공동 1등 보상)
  - 나머지 등수는 탈락 순서. 같은 순간 탈락하면 동순위
- **재미**: 벽이 생겼다 풀렸다 하는 흐름 읽기, 틈으로 먼저 빠져나가는 순간 판단, 공동 승리라 협력과 경쟁이 섞임
- **장점**: 고정 화면이라 Swing 구현 쉬움 (줄 단위 이동). 클러셔가 오는 게 보이니까 지연에 비교적 강함. 형식은 개인전 (2~4인)
- **동시성**
  - **클러셔 1마리 = 스레드 1개, 속도 = 각자 다른 이동 간격**. 속도 차이가 스레드마다 다른 sleep 간격으로 자연스럽게 표현됨
  - **벽이 생기는 원리 = 칸 확보 경쟁**: 클러셔는 다음 칸을 확보해야만 이동 가능 → 앞 칸에 느린 애가 있으면 대기 → 줄이 쌓여서 벽이 됨. 게임 규칙이 동시성 규칙에서 저절로 나옴
  - **동시 밀림**: 플레이어가 움직이는 순간 클러셔가 밀고, 두 마리가 동시에 밀 수도 있음 → 플레이어 위치 갱신을 원자적으로
  - **연쇄 밀림 (선택)**: 클러셔가 플레이어를 밀고 그 플레이어가 다른 플레이어를 밀면 여러 객체를 같이 잠가야 함 → x좌표 순으로 잠가서 데드락 방지
  - **종료 판정 경쟁**: 시간 종료 타이머와 마지막 탈락이 같은 순간에 일어나면? `AtomicBoolean` CAS로 먼저 들어온 쪽만 종료 처리
  - 생존자 수는 `AtomicInteger.decrementAndGet`으로 관리, 1이 되는 순간 종료
- **정해야 할 것**
  - [ ] 클러셔에 닿으면 **밀리기만** 하는지, 닿는 순간 **바로 탈락**인지 (기준안: 밀리기만, 떨어져야 탈락)
  - [ ] 플레이어끼리 서로 밀 수 있게 할지 (넣으면 연쇄 밀림 처리 필요)
  - [ ] 틈이 반드시 생기도록 보장할지, 완전 랜덤으로 둘지 (기준안: 일정 시간마다 최소 1개 틈 보장)
  - [ ] 시간이 갈수록 클러셔 속도/수 증가 여부

### 14. 코인 눈치게임 (참고: 슈퍼 마리오 파티 "코인을 모으자")

- **진행**
  - 3x3 구름 위에 코인이 1~3개씩 놓임 (빈 구름도 있음)
  - 제한시간 안에 모두 **동시에** 갈 구름을 고름 (서로의 선택은 안 보임)
  - 한꺼번에 점프 → **혼자 고른 구름**의 코인만 획득, **같은 구름을 고르면 아무도 못 먹음**
  - 코인 다시 배치 후 여러 턴 반복, 최종 코인 수로 등수
- **재미**: 순수 심리전. "3개짜리는 다들 갈 테니까 난 2개" → "그렇게 생각할 테니까 난 3개" 같은 수 읽기. 조작 실력 무관
- **장점**
  - **지연에 가장 강함**: 동시 선택 후 공개라 핑이 결과에 영향 없음. 터널링 환경에 최적
  - Swing 구현 매우 쉬움 (3x3 버튼/그리드 + 공개 연출)
  - 아이템 단계 동시 발동과 **같은 메커니즘**이라 코드 재사용 가능
- **동시성**
  - **`CyclicBarrier`가 딱 맞는 자리**: 전원 선택 → 공개 → 다음 턴. 턴마다 같은 배리어를 재사용 (이름이 cyclic인 이유). 배리어 해제 액션에서 판정 실행
  - **먼저 온 사람이 임자가 아님**: "먼저 잡은 사람이 먹기"(CAS)로 짜면 틀린 구현. 전원 커밋을 기다린 뒤 구름별 인원을 세야 함 → 왜주기 줄에 "먼저 온 사람 우선"과 대비되는 예시
  - **선택 숨기기**: 서버는 전원 제출 전까지 누가 뭘 골랐는지 절대 broadcast하면 안 됨 (패킷 엿보기 방지). "제출함" 여부만 알려줌
  - **시간 초과**: 미제출자는 랜덤 or 제자리. `await(timeout)` + 깨진 배리어(BrokenBarrierException) 처리까지 다뤄볼 수 있음
  - **도중 이탈**: 배리어 참가 인원이 줄어야 함 → 인원 변동이 있으면 `Phaser`가 더 맞음 (두 방식 비교 가능)
- **인원 보정**: 2인이면 9칸 중 겹칠 확률이 낮아 심심함 → 코인 있는 구름 수를 **인원 + 1~2개**로 제한해서 충돌 유도
- **정해야 할 것**
  - [ ] 겹쳤을 때 패널티 (기준안: 아무도 못 먹음 / 선택: 가진 코인 1개씩 잃음)
  - [ ] 턴 수, 턴당 선택 시간 (기준안: 5턴, 5초)
  - [ ] 남은 코인이 다음 턴까지 쌓이는지 (쌓이면 판이 커져서 심리전 강해짐)

### 15. 물풍선 폭탄 (참고: 크레이지아케이드)

- **진행**: 격자 맵, 부서지는 블록과 안 부서지는 벽. 폭탄을 놓으면 일정 시간 뒤 십자로 터짐. 블록을 부수면 아이템(폭탄 개수+, 화력+, 속도+)이 나옴. 맞으면 탈락
- **승리**: 마지막 생존자. 시간 종료 시 생존자 공동 승리 (또는 서든데스: 맵이 줄어듦)
- **재미**: 내가 놓은 폭탄에 내가 갇히는 상황, 연쇄 폭발로 한방에 여러 명 잡기, 아이템 섭취 경쟁
- **장점**: 격자 기반이라 Swing 구현 쉬움. 폭탄 터지기까지 시간이 있어서 지연에 비교적 강함
- **동시성** (후보 중 가장 풍부함)
  - **폭탄 개수 제한 = `Semaphore`**: 놓을 때 `tryAcquire`, 터질 때 `release`. "폭탄 개수+" 아이템은 허가를 하나 더 `release`
  - **연쇄 폭발**: A의 화염이 B를 터뜨리고, B의 타이머도 동시에 끝남 → B가 두 번 터지면 안 됨. `AtomicBoolean exploded` CAS로 딱 한 번만
  - **서로가 서로를 터뜨리는 경우**: 락으로 짜면 데드락 가능 → CAS로 해결
  - **블록을 두 화염이 동시에 부수면** 아이템이 두 개 나오면 안 됨 (칸 상태 CAS)
  - **같은 칸에 동시에 폭탄 놓기**, **아이템 동시 섭취**, **두 폭탄에 동시에 맞았을 때 킬은 누구 것인가**
  - 폭탄 타이머는 `ScheduledExecutorService`
- **변형 (선택)**: **2:2 팀전** (크아처럼 갇힌 팀원을 터치해서 구출). 4인 전용 후보로 돌릴 수 있음
- **주의**: 크레이지아케이드 원본 이름/스프라이트는 넥슨 저작권. GitHub이나 포트폴리오에 올릴 거면 직접 만든 그림과 다른 이름 사용

### 16. 가시 롤러 (2:2 팀전)

- **형식**: 2:2 팀전 (4인 전용). 2명이 한 팀으로 묶임
- **역할 분담**: 한 명은 **위로 점프만**, 한 명은 **아래로 숙이기만** 가능. 혼자서는 모든 롤러를 피할 수 없음
- **진행**: 용암으로 둘러싸인 발판, 가시 롤러가 쓸고 지나감. 못 피하면 용암 쪽으로 밀려나고, 빠지면 탈락
  - 롤러 높이 (기준안): 낮은 롤러는 점프 담당이, 높은 롤러는 숙이기 담당이 피함
- **가속**: 시간이 갈수록 롤러가 빨라짐
- **재미**: 팀원끼리 호흡 맞추기, 내 차례가 아닐 때 섣불리 누르면 안 되는 긴장
- **동시성**
  - **팀 상태를 한 번에 읽기**: 롤러가 닿는 순간 "A가 점프 중인가"와 "B가 숙인 상태인가"를 따로 읽으면 그 사이 값이 바뀌어 잘못 판정할 수 있음 → 팀 상태를 불변 객체로 묶어 `AtomicReference`로 통째로 교체하거나, 팀 단위로 잠가서 읽기
  - **가속도 값의 가시성**: 가속 타이머 스레드가 속도를 올리고 롤러 스레드가 읽음. `volatile`이 없으면 롤러가 바뀐 속도를 못 볼 수 있음 → `volatile`을 직접 보여주는 예시
  - **시간 기반 위치 계산**: "매 틱 +속도"로 누적하면 스레드 스케줄링 오차가 쌓임 → 경과 시간으로 위치를 계산해서 오차 제거
  - 시간 종료 vs 마지막 팀 탈락 동시 발생 → CAS로 종료 처리 한 번만
- **주의**: 점프·숙이기는 타이밍 입력이라 지연에 약함. 롤러 예고를 길게 주고 판정에 여유를 둬야 함
- **정해야 할 것**
  - [ ] 두 사람이 캐릭터 하나를 같이 조작하는지, 캐릭터 둘이 묶여 있는지
  - [ ] 두 팀이 같은 발판에서 하는지, 팀별 레인을 따로 두는지
  - [ ] 롤러에 맞으면 밀리기만 하는지, 바로 탈락인지
  - [ ] 두 팀 다 제한시간까지 버티면? (무승부 / 맞은 횟수로 판정)
  - [ ] 가속 공식 (예: 속도 = 기본 + a x 경과초, 최대값 제한)
