# 스레드 구조도 v1: 스레드와 큐 (2026-10-25)

> M0(콘솔 채팅) 기준. 스레드가 몇 개이고 누가 무엇을 만지는지까지.

## 전체도

`overview.py`

```
    +------------+                                  +------------------------+
    |  Client A  |                                  | Server 100.x.x.x:5000  |
    +------------+                                  +------------------------+

+--------------------+            +-------------------------------------------------------+
|                    |            |                                                       |
|  +--------------+  |            |                                   +-----------------+ |
|  | Input (main) |  |            |                                   |     Accept      | |
|  +--------------+  |            |                                   +-----------------+ |
|         |          |            |                               new client ->           |
|         v          |            |                               Recv + Send             |
|  +--------------+  |            |                                                       |
|  |  sendQueue   |  |            |                     +----------------+                |
|  +--------------+  |            |               +---->|   inputQueue   |<-----------+   |
|         |          |            |               |     +----------------+            |   |
|         v          |            |               |             |                     |   |
|  +--------------+  |      +-----+------------+  |             |                     |   |
|  |     Send     |---TCP-->|     | Recv A     |--+             v                     |   |
|  +--------------+  |      +-----+------------+        +----------------+            |   |
|  +--------------+  |      +-----+------------+        |    GameLoop    |            |   |
|  |Recv -> print |<--TCP---|     | Send A [Q] |<-------|    1 thread    |            |   |
|  +--------------+  |      +-----+------------+   +----|    20~30Hz     |            |   |
|                    |            |                |    +----------------+            |   |
+--------------------+            |                |                                  |   |
                                  |                |                                  |   |
  +----------------+        +-----+------------+   |                                  |   |
  | Recv           |<-TCP---|     | Send B [Q] |<--+                                  |   |
  | Client B       |        +-----+------------+                                      |   |
  | (same as A)    |        +-----+------------+                                      |   |
  | Send           |--TCP-->|     | Recv B     |--------------------------------------+   |
  +----------------+        +-----+------------+                                          |
                                  |                                                       |
                                  |                                                       |
                                  +-------------------------------------------------------+
```

## 스레드별 역할

| 스레드 | 개수 | 하는 일 | 만질 수 있는 것 |
|---|---|---|---|
| **서버 Accept** | 1 | `accept()`로 접속을 기다리다가 접속마다 Recv·Send 스레드와 송신 큐를 만듦 | 서버 소켓 |
| **서버 Recv X** | 접속당 1 | 소켓에서 한 줄 읽기 → 파싱 → `inputQueue`에 넣기 | 자기 소켓 입력, `inputQueue` (넣기만) |
| **서버 GameLoop** | 1 | `inputQueue` 비우기 → 상태 갱신 → 보낼 메시지를 각 세션 송신 큐에 넣기 | **게임 상태 전부**, 세션 목록 |
| **서버 Send X** | 접속당 1 | 자기 송신 큐에서 `take()` → 소켓에 쓰기 | 자기 소켓 출력 |
| 클라 Input | 1 | 키보드(M0는 콘솔) 입력 → `sendQueue` | `sendQueue` (넣기만) |
| 클라 Send | 1 | `sendQueue`에서 `take()` → 소켓에 쓰기 | 소켓 출력 |
| 클라 Recv | 1 | 소켓에서 읽기 → 출력 (GUI에서는 `invokeLater`로 EDT에 넘김) | 소켓 입력 |

스레드 수: 서버 = 2 + 2 × 접속 수 (4인이면 10개), 클라이언트 = 3개.

## 채팅 한 줄이 지나가는 순서

1. A의 **Input**이 "안녕"을 읽어 `sendQueue`에 넣음
2. A의 **Send**가 꺼내서 소켓에 씀 → TCP
3. 서버 **Recv A**가 한 줄 읽고 파싱해서 `inputQueue`에 넣음
4. **GameLoop**가 다음 tick에 꺼냄
5. GameLoop가 같은 메시지를 **Send A [Q]**, **Send B [Q]**에 각각 넣음 (broadcast)
6. **Send A / Send B**가 각자 꺼내서 소켓에 씀
7. A·B의 **Recv**가 받아서 출력

## 지켜야 할 것

- **소켓에 쓰는 건 Send 스레드뿐.** 다른 스레드가 쓰면 두 메시지가 한 줄에 섞임. 클라이언트 Recv가 PING에 PONG으로 답할 때도 직접 쓰지 않고 `sendQueue`에 넣음 (클라이언트에도 송신 큐가 있는 이유)
- **게임 상태를 바꾸는 건 GameLoop뿐.** Recv는 넣기만 하므로 상태에 락이 필요 없음
- **느린 클라이언트는 자기 Send만 막힘.** 큐가 사이에 있어서 GameLoop와 다른 사람 Send는 계속 돎

## 접속이 끊길 때 (기준안)

1. **Recv X**가 `readLine()`에서 `null`(정상 종료)이나 예외(강제 종료)를 받음
2. Recv X가 "X 나감" 이벤트를 `inputQueue`에 넣고 끝남
3. **GameLoop**가 세션 목록에서 X를 빼고 퇴장 알림을 broadcast
4. **Send X**는 송신 큐에 종료 신호를 받거나 인터럽트되어 소켓을 닫고 끝남

세션 목록에서 빼는 일도 GameLoop만 하므로, broadcast 도중 목록이 바뀌는 문제가 없음.
