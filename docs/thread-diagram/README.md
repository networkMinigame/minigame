# 스레드 구조도

서버·클라이언트의 스레드, 큐, 소켓 관계를 그림으로 쌓아 가는 곳. 버전마다 디렉터리로 스냅샷을 남기고, 새 버전은 이전 버전보다 더 자세히 그린다.

| 버전 | 날짜 | 내용 |
|---|---|---|
| [v1](v1/) | 2026-10-25 | 전체도: 스레드와 큐, 누가 무엇을 만지는지 |
| [v2](v2/) | 2026-10-25 | 세션 목록은 GameLoop 소유 + 확대도: 입장·채팅·핑, 나감, 메시지 목록 (**현재 기준**) |

## 버전 규칙

- 지난 버전은 고치지 않는다. 바뀌면 새 버전 디렉터리를 만든다
- 버전 디렉터리의 `README.md`가 전체도. 맨 위에 "이전 버전 대비 바뀐 것"을 적는다
- 확대도는 전체도의 박스나 화살표 하나를 펼친 것. 같은 디렉터리에 별도 `.md`로 두고 전체도에서 링크한다
- ASCII 그림은 찍은 스크립트(`.py`)를 그림 옆에 둔다

## 그림 종류

| 그림 | 형식 | 이유 |
|---|---|---|
| 전체도 (스레드·큐 배치) | ASCII | 프로세스 테두리에 걸친 박스를 Mermaid로 못 그림 |
| 시퀀스 (시간 순서) | Mermaid `sequenceDiagram` | 한글 라벨이 안 깨지고 `loop`·`alt` 블록을 씀. GitHub·IntelliJ 미리보기에서 그림으로 보임 |

## 시퀀스 규칙 (Mermaid)

- 서버 안 스레드는 `box Server ... end`로 묶어 참여자로 둔다
- 실선(`->>`) = TCP, 점선(`-->>`) = 서버 안 큐, 끝이 ✕(`-x`) = 끊긴 연결
- 서버 안에서 일어나는 판단은 `Note over`로 적는다

## 전체도 규칙 (ASCII)

- 큰 박스 = 프로세스 (서버 PC, 클라이언트 PC). 위에 제목 박스
- 프로세스 테두리에 걸친 박스 = 클라이언트 하나와 연결된 세션 스레드. 바깥(소켓)과 안(큐)을 잇는다
- 안쪽 박스 = 스레드나 큐, 화살표 = 데이터가 가는 방향
- `[Q]` = 그 스레드가 꺼내 쓰는 송신 큐 (`LinkedBlockingQueue`)
- 박스 안 라벨은 영문·코드 이름만. 한글은 고정폭 글꼴에서 2칸이라 정렬이 깨진다. 설명은 그림 아래 한글로
- 선이 교차하지 않게 배치한다 (v1의 B가 Send/Recv 순서인 이유)

## 그리는 법

손으로 공백을 맞추지 않고 파이썬 스크립트로 찍는다. 새 버전은 이전 버전 스크립트를 복사해서 고친다.

```bash
python docs/thread-diagram/v2/overview.py    # 출력을 v2/README.md 코드 블록에 붙여넣기
```

`canvas.py`: `Canvas`(`box` 박스+라벨, `h`/`v` 선, `put` 글자)
