# 스레드 구조도

서버·클라이언트의 스레드, 큐, 소켓 관계를 그림으로 쌓아 가는 곳.

| 버전 | 내용 |
|---|---|
| [v1](v1/) | 전체도 (스레드와 큐, 누가 무엇을 만지는지) + 확대도: 입장·채팅·핑, 나감, 메시지 목록, 세션 안쪽·닫기 |

**스레드·큐 이름과 규칙의 단일 출처.** 이름은 현재 버전 `README.md`의 "이름" 표에만 정의한다. `architecture.md`, `.coderabbit.yaml` 등 다른 곳은 이름을 다시 풀어 쓰지 않고 이 디렉터리를 링크한다. 이름이 바뀌면 여기를 고치고, 다른 문서 본문에서 옛 이름을 검색해 바꾼다.

## 버전 규칙

- 구조가 정해지는 동안에는 **기존 버전을 계속 고친다.** 커밋한 버전이어도 바뀐 내용은 그 자리에 반영한다
- 이전 그림을 남겨 둘 이유가 생기면 그때 새 버전 디렉터리를 만든다
- 버전 디렉터리의 `README.md`가 전체도. 확대도는 전체도의 박스나 화살표 하나를 펼친 것으로, 같은 디렉터리에 별도 `.md`로 두고 전체도에서 링크한다

## 그림 종류

| 그림 | 형식 | 이유 |
|---|---|---|
| 전체도 (스레드·큐 배치) | SVG, 파이썬으로 생성 | 프로세스 테두리에 걸친 박스를 그대로 그리고 색·한글을 씀. Mermaid로는 이 배치가 안 됨 |
| 시퀀스 (시간 순서) | Mermaid `sequenceDiagram` | `loop`·`alt` 블록을 씀. GitHub·IntelliJ 미리보기에서 그림으로 보임 |

## 전체도 규칙 (SVG)

- 큰 회색 박스 = 프로세스 (서버 PC, 클라이언트 PC). 위에 제목 박스
- 프로세스 테두리에 걸친 박스 = 클라이언트 하나와 연결된 세션 스레드. 바깥(소켓)과 안(큐)을 잇는다
- 박스 색: 파랑 = 스레드, 노랑 = 큐 (또는 큐를 가진 스레드), 초록 = GameLoop
- 선 색: 회색 = TCP, 파랑 = 받는 길, 초록 = 큐 → GameLoop, 노랑 = 보내는 길
- 선이 교차하지 않게 배치한다 (B의 세션 스레드가 Writer/Reader 순서인 이유)

색과 그리기 함수는 `svg.py`가 단일 출처.

## 시퀀스 규칙 (Mermaid)

- 서버 안 스레드는 `box Server ... end`로 묶어 참여자로 둔다
- 실선(`->>`) = TCP, 점선(`-->>`) = 서버 안 큐, 끝이 ✕(`-x`) = 끊긴 연결
- 서버 안에서 일어나는 판단은 `Note over`로 적는다

## 전체도 다시 그리기

`overview.py`의 좌표·라벨을 고치고 실행하면 같은 디렉터리의 `overview.svg`가 갱신된다.

```bash
python docs/thread-diagram/v1/overview.py
```
